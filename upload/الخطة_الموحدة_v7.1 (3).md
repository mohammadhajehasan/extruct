## 3.1 جلب كل النماذج المتاحة للمفتاح
```python
ALWAYS_FREE_URLS = ("http://localhost:11434/v1", "https://api.groq.com/openai/v1")
VISION_HINTS = ("vl","vision","gemini","gpt-4o","gpt-4.1","pixtral",
                "llava","minicpm","internvl","molmo","claude-3")

def _is_free(name, meta, url):
    if any(url.startswith(u) for u in ALWAYS_FREE_URLS): return True
    n = name.lower()
    if ":free" in n or n.endswith("-free"): return True
    if meta:  # OpenRouter يعرض التسعير ضمن /models
        try:
            pr = meta.get("pricing", {})
            if float(pr.get("prompt",1))==0 and float(pr.get("completion",1))==0:
                return True
        except (TypeError, ValueError): pass
    return False

def fetch_models(base_url, api_key, timeout=20):
    client = openai.OpenAI(api_key=api_key or "ollama", base_url=base_url, timeout=timeout)
    return [{"name": m.id,
             "free": _is_free(m.id, getattr(m,"model_extra",None) or {}, base_url),
             "vision": any(h in m.id.lower() for h in VISION_HINTS)}
            for m in getattr(client.models.list(), "data", [])]

def sort_models(models):   # ★ مجاني رؤيوي أولاً دائماً
    return sorted(models, key=lambda m:(not m["free"], not m["vision"], m["name"]))
```
- **سلوك الواجهة:** إدخال المفتاح ← جلب تلقائي مؤجل (700ms) + زر 🔄 يدوي؛
  وسوم ⭐مجاني/💳مدفوع/👁رؤيوي/📄نصي + فلتر "الرؤيوية فقط"؛
  **Fallback مدمج** لقائمة احتياطية عند فشل الجلب؛ أول مجاني رؤيوي = الافتراضي.
- المزودات المدعومة: OpenRouter / Qwen DashScope / Gemini / Groq / Ollama / OpenAI / مخصص.

## 3.2 وضع مقارنة النماذج (Benchmark)
```python
def benchmark(img, models, extract, score):
    res = {m: extract(img, m) for m in models}
    sc  = {m: score(res[m]) for m in models}
    return res, sc, pairwise_agreement(res), max(sc, key=sc.get)
```
تبويب لكل نموذج (CSV+درجة) + مصفوفة توافق + شارة 🏆 + زر اعتماد + تقرير CSV.

# الجزء 4: وحدة PDF (core/pdfio.py)

```python
import fitz
def pdf_pages(path, dpi=300):
    out=[]
    for i,pg in enumerate(fitz.open(path)):
        # ★ مرشّح سريع (Fast Pre-Filter) قبل استدعاء find_tables() المكلفة:
        # جدول حقيقي مرسوم بالـ PDF يحتاج خطوط/مستطيلات فعلية (vector drawings).
        # صفحة صورة ممسوحة (حتى لو فيها طبقة نص OCR خفية) لن يكون فيها رسومات كافية.
        has_text = bool(pg.get_text().strip())
        has_enough_drawings = len(pg.get_drawings()) >= 4   # عتبة دنيا رخيصة الحساب
        if has_text and has_enough_drawings and pg.find_tables().tables:
            out.append(("native", i, [t.extract() for t in pg.find_tables().tables]))
        else:
            pix = pg.get_pixmap(dpi=dpi)
            out.append(("image", i, np.frombuffer(pix.samples,np.uint8)
                                    .reshape(pix.h,pix.w,pix.n)))
    return out   # تحذير إن dpi<200
```
- **مرشّح `get_drawings()`:** رخيصة جداً مقارنة بـ `find_tables()` (فحص عدد كائنات رسم بسيط لا تحليل هندسي كامل)؛ تستبعد فوراً كل صفحة ممسوحة ذات طبقة OCR نصية بدون استدعاء `find_tables()` إطلاقاً — هذا وحده يقطع الغالبية العظمى من وقت الفحص الضائع على الملفات الممسوحة (راجع 15.9.1 للتفاصيل والأرقام).
- **PDF نصي:** جداول أصلية ← صفوف مباشرة بدقة 100% بلا نموذج.
- **PDF ممسوح:** كل صفحة صورة ← خط التحسين/الاستخراج الكامل.
- **ترتيب الجداول:** ترتيب الملف + `auto_order` اختياري.
- **PDF الميكانيك:** تصنيف صفحات ← تجميع وجوه ← سجلات **بترتيب ورودها في الملف**.

# الجزء 6: التحسين الآمن (موسوعة التقنيات + الحلقة الذاتية)

## 6.1 قواعد الأمان
⛑ NLM قوي على النص • ⛑ Unsharp قوي (هالات) • ⛑ Binarization مع VL •
CLAHE ≤1.2 • التغميق = Close(2×2) • الختام = Stretch(2–98) • بوابة جودة تقترح لا تفرض.

## 6.2 مصفوفة القرار
| العَرَض | الحل | الممنوع |
|---|---|---|
| باهت | CLAHE(1.2)+Close+Stretch | equalizeHist |
| ظل/تدرج | قسمة خلفية σ75 | CLAHE قوي وحده |
| حروف متكسرة | Close(2×2) فقط | NLM / Otsu |
| ضبابية | تكبير×2 + Micro-Unsharp(1.3/σ1.5) | Unsharp قوي |
| ضجيج | Bilateral | NLM قوي |
| ميل/زاوية | Deskew / منظور | تجاهلها |
| ختم | قناع HSV + Inpaint | تركه |
| دقة صغيرة | superres ثم الخط | تكبير بسيط وحده |

## 6.3 البروفايلات
بدون • **تغميق ووضوح⭐** (upscale→gray→shadow→clahe→close→micro→stretch) •
يدوي آمن • ظل قوي • ضجيج عالي آمن • دقة منخفضة • مختوم •
**وثيقة رسمية** (gray→shadow σ60→clahe_micro→close→stretch — بلا sharpen حماية للأختام).

## 6.4 المحلِّل/المخطِّط/الضابط/KB
عتبات: blur<120، std<45، زاوية>1°، منظور>3°، ضجيج>0.35، دقة<1600، ختم>0.5%.
`RULES` مرتبة الأولوية تبني السلسلة مع تسجيل **السبب** لكل خطوة.
Tuner يجرب ≤3 سلاسل ويتوقف عند العتبة ويحفظ الأفضل في KB.

## 6.5 تقنيات المستندات الخاصة
تقوية شبكة الجدول • تطبيع لكل خلية • توحيد إضاءة صفحات الوثيقة •
حماية السمك الخطي (Distance Transform) • قص ROI ذكي • إزالة ختم تلقائية.

# الجزء 8: هندسة الدقة الأسطورية

1. **JSON ثابت المفاتيح** ← لا انزياح أعمدة أبداً ثم تحويل لجدول.
2. **Verifier مرور ثانٍ:** مقارنة كل قيمة بالصورة وإ JSON تصحيحات بثقة HIGH/MED/LOW.
3. **إعادة قراءة مكبّرة** لكل UNCLEAR/LOW بقصّ منطقي وسؤال منفرد.
4. **إجماع + مقارنة نماذج**؛ خلاف ← MED/REVIEW.
5. **طابور تدقيق** (<10% من الحقول) بقصّات مكبرة واختيار بنقرة.
6. **تعلم:** كل تصحيح ← KB (crop_hash، خطأ، صواب) ← few-shot للحالات المشابهة.
7. **Human Baseline لكل فئة** = الهدف الرسمي لكسر خطأ الإنسان.
8. **معزِّزات إضافية:** كشف نوع الوثيقة تلقائياً • حارس DPI • استئناف وكاش •
   نسخ احتياطي تلقائي • خريطة لبس مُعلَّمة • تقرير جلسة تدقيقي كامل.

## 15.1 تحقق رياضي من رقم الهيكل (VIN Check Digit — ISO 3779)

رقم الهيكل لأغلب المركبات مكوّن من 17 خانة وله خانة تحقق (check digit) في الموضع التاسع يمكن حسابها رياضياً. أي قيمة يستخرجها النموذج تُتحقق منها فوراً بلا كلفة إضافية:

```python
VIN_MAP = {**{c:v for c,v in zip("ABCDEFGH",[1,2,3,4,5,6,7,8])},
           **{c:v for c,v in zip("JKLMNPRSTUVWXYZ",[1,2,3,4,5,7,9,2,3,4,5,6,7,8,9])},
           **{str(d):d for d in range(10)}}
WEIGHTS = [8,7,6,5,4,3,2,10,0,9,8,7,6,5,4,3,2]

def vin_check_digit_valid(vin: str) -> bool:
    if len(vin) != 17 or not vin.isalnum(): return False
    if any(c.upper() in "IOQ" for c in vin): return False   # محظورة رسمياً بمعيار VIN
    total = sum(VIN_MAP.get(c.upper(),0)*w for c,w in zip(vin, WEIGHTS))
    remainder = total % 11
    expected = "X" if remainder == 10 else str(remainder)
    return vin[8].upper() == expected
```
- نتيجة سالبة ← `chassis_no` يُعلَّم REVIEW تلقائياً **حتى لو ثقة النموذج HIGH**.
- لا يُستخدم لتصحيح الرقم تلقائياً (احتراماً لمبدأ "انقل ولا تُصحّح")، فقط للتشكيك وطلب مراجعة/إعادة قراءة مكبّرة.
- ملاحظة: بعض المركبات الأقدم (قبل 1981) قد لا تتبع المعيار — تُستثنى تلقائياً بفحص طول/نمط الرقم قبل التطبيق.

### ⚠️ توضيح إلزامي لأي مطوّر — لا يوجد تحويل على قيمة الاستخراج أبداً

يجب عدم الخلط بين **قيمة الاستخراج المخزَّنة** و**الحساب الداخلي المؤقت للتحقق** — هما مساران منفصلان تماماً ولا يجب دمجهما بالكود بأي شكل:

| | القيمة | أين تعيش | هل تُخزَّن/تُصدَّر؟ |
|---|---|---|---|
| **قيمة `chassis_no` الفعلية** | محارف كما استخرجها النموذج حرفياً، مثال: `"KNARH81E7T5404488"` | عمود `chassis_no` بالجدول/Excel/JSON | ✅ نعم — هذه هي النتيجة النهائية التي يراها المستخدم |
| **تحويل `VIN_MAP` الرقمي** | أرقام مؤقتة (K=2, N=5, A=1...) تُستخدم فقط داخل حساب المجموع | متغيرات محلية داخل `vin_check_digit_valid()` فقط، تُرمى فور انتهاء الدالة | ❌ أبداً — لا تُكتب لأي عمود، ولا تُمرَّر خارج الدالة، ولا تظهر بأي تقرير |

**القاعدة الملزمة للتنفيذ:**
```python
# ✅ صحيح — الدالة تُستدعى للتحقق فقط، ونتيجتها Boolean منفصل بعمود ثقة إضافي
record["chassis_no"] = vl_extracted_value                       # يبقى كما هو حرفياً، بلا لمسة
record["chassis_no_vin_valid"] = vin_check_digit_valid(vl_extracted_value)  # True/False فقط بعمود جانبي

# ❌ ممنوع تماماً — أي كود يستبدل أو "يصحّح" القيمة المخزّنة بناءً على vin_check_digit_valid
# record["chassis_no"] = corrected_value   # ← هذا ممنوع ويخالف مبدأ "انقل ولا تصحّح"
```
أي مراجعة كود (Code Review) بالمرحلة 6/7 من خارطة الطريق (الجزء 13) يجب أن تتأكد صراحةً أن نتيجة `vin_check_digit_valid()` لا تُستخدم إلا لتعيين علم REVIEW/HIGH بعمود ثقة منفصل، ولا تُمرَّر أبداً كقيمة بديلة لعمود `chassis_no` نفسه.

## 15.3 طبقة تحقق مزدوجة بمحرك OCR تقليدي للحقول الرقمية

def cross_verify_numeric(field_name, vl_value, crop_img):
    ocr_value = run_ocr(crop_img, whitelist="0123456789ABCDEFGHJKLMNPRSTUVWXYZ-/")
    if normalize(ocr_value) == normalize(vl_value):

## 15.8 واجهة إدخال الصور المتعددة — ترتيب/معاينة/تبديل/تعديل قبل الاستخراج

الخطة v7.0 غطت ترتيب الصفحات **داخل ملف PDF واحد** (7.3، 4) لكنها لم تُفصّل حالة: (أ) المستخدم يرفع **عدة صور منفصلة دفعة واحدة** بدل PDF، (ب) يريد **تغيير ترتيبها يدوياً/تبديل موضعين/حذف/معاينة مكبّرة/تحرير كل صورة على حدة** قبل الضغط على استخراج، (ج) هذه الصور المتعددة (أو صفحات PDF) قد تحوي **الأنواع الأربعة من الميكانيك مجتمعة** بأي ترتيب عشوائي، وليس فقط ضمن PDF واحد بل حتى لو جاءت كصور مستقلة مرفوعة معاً. هذا البند يسدّ الفجوة وينطبق على **الوضعين معاً**: استخراج الجداول العام (Part 4) واستخراج الميكانيك (Part 7).

### 15.8.1 طابور إدخال موحّد (Unified Input Queue)

كل مصدر إدخال — صور مفردة متعددة، أو PDF واحد أو أكثر، أو مزيج من الاثنين بنفس العملية — يتحوّل فوراً لعناصر بقائمة واحدة مرتّبة قابلة للتعديل، بغض النظر عن مصدرها الأصلي:

```python
class QueueItem:
    id: str
    source: Literal["upload_image", "pdf_page"]
    source_file: str          # اسم الصورة أو ملف PDF الأصلي (للتتبع بالتدقيق)
    image: np.ndarray         # بعد أي تحرير مطبَّق
    edits: list[dict]         # مكدس عمليات editor.py (7.6/الجزء5) الخاص بهذا العنصر تحديداً
    category_auto: str        # نتيجة التصنيف الآلي: mechanic_card_front/back | vehicle_record | temp_license | ownership_deed | other
    category_override: str | None   # تصحيح المستخدم اليدوي إن اختلف مع الآلي
    order_index: int          # قابل للتغيير بالسحب والإفلات
```
- الترتيب النهائي المستخدم بالاستخراج (سواء دمج جدول أو تجميع وجوه ميكانيك) = `order_index` كما ضبطه المستخدم بالواجهة، **وليس** بالضرورة ترتيب الرفع الخام.
- `pdf_page` تتحول لعناصر `QueueItem` فور المعالجة بـ `pdf_pages()` (الجزء 4)، فتدخل نفس الطابور وتخضع لنفس أدوات الترتيب/التحرير كأي صورة مرفوعة مباشرة — لا فرق بمصدرها بعد هذه اللحظة.

### 15.8.2 شريط المصغّرات (Thumbnail Strip) — نفس المكوّن لوضعي الجداول والميكانيك

```
[▤ سحب] [صورة1 🏷️بطاقة-أمامي] [صورة2 🏷️بطاقة-خلفي] [صورة3 🏷️بيان قيد] [صورة4 🏷️سند تمليك] ...
   ↑ مقبض سحب لإعادة الترتيب        ↑ شارة التصنيف الآلي (قابلة للتعديل بنقرة)
```
- **سحب وإفلات (Drag & Drop):** يعيد ترتيب `order_index` مباشرة لكل العناصر المتأثرة.
- **تبديل ثنائي سريع (Swap):** تحديد عنصرين بـ Ctrl/Shift-click ثم زر "تبديل الموضعين" — أسرع من السحب لتصحيح خطأ موضعي بسيط دون تحريك بقية القائمة.
- **معاينة مكبّرة (Preview):** نقرة على المصغّرة تفتح نفس نافذة `ui/editor.py` (الجزء 5) بكل أدواتها (تدوير/قص/سطوع/حدة/تحسين) — أي تعديل يُطبّق على عنصر الطابور فقط، والأصل بالذاكرة يبقى سليماً (نفس مبدأ "غير إتلافي" بالجزء 5).
- **حذف/تكرار عنصر:** لصورة رديئة يريد المستخدم استبعادها، أو لتكرار صورة لتجربة تصنيف مختلف يدوياً.
- **شارة التصنيف قابلة للتعديل يدوياً دائماً:** إن أخطأ المصنّف الآلي (مثلاً صنّف بيان قيد كسند تمليك)، يختار المستخدم التصنيف الصحيح من قائمة منسدلة فوق المصغّرة مباشرة قبل الاستخراج؛ `category_override` تُستخدم بدل `category_auto` بالتجميع (7.3).

### 15.8.3 دعم الفئات المختلطة عبر مصادر متعددة (وليس فقط داخل PDF واحد)

منطق `group_faces()` بالجزء 7.3 كان يفترض ضمنياً مصدراً واحداً متسلسلاً (PDF). الآن يُطبَّق على **طابور موحّد** بغض النظر عن كون عناصره جاءت من عدة صور مرفوعة يدوياً، عدة ملفات PDF، أو مزيج من الاثنين برفعة واحدة:

```python
def process_unified_queue(queue: list[QueueItem]):
    queue.sort(key=lambda q: q.order_index)          # احترام ترتيب المستخدم النهائي أولاً
    labeled = [(q.category_override or q.category_auto, q.image) for q in queue]
    records = group_faces(labeled)                    # نفس دالة 7.3 دون تعديل — تعمل بلا وعي بمصدر كل صورة
    for rec in records:
        rec.source_files = [queue[i].source_file for i in rec.matched_indices]  # تتبّع الملف الأصلي لكل سجل بالتدقيق
    return records
```
- مثال عملي: يرفع المستخدم دفعة واحدة تضم: `card_front.jpg` + `card_back.jpg` + `PDF فيه بيان قيد وسند تمليك` + `صورة رخصة سير مستقلة` — كلها تدخل نفس الطابور، يرتّبها المستخدم بالسحب حسب ما يريد (مثلاً حسب المركبة)، ثم استخراج واحد يُخرج 4 سجلات مصنّفة بشكل صحيح بجدول واحد، وكل سجل يحمل بعمود `source_files` أي ملف أصلي جاء منه (للتتبع والتدقيق فقط، الجزء 9).
- إن حصل تعارض ترتيب يكسر تجميع وجهي الكرت (مثلاً المستخدم وضع صورة أخرى بينهما بالسحب)، تنطبق نفس آلية 15.2 (مطابقة بالباركود) كخط دفاع أول قبل الاعتماد على التجاور بالطابور.

## 15.9 ملحق أداء رسمي — معالجة ملفات PDF كبيرة/متعددة الصفحات (v7.1)

> يُضاف بعد ملاحظة أداء فعلية: تراكم 4 عوامل معاً (فحص `find_tables` لكل صفحة + رسترة 300DPI لكل صفحة ممسوحة + استدعاء النموذج بالتسلسل + عدد صفحات كبير) يجعل معالجة ملف واحد تأخذ دقائق طويلة. الحلول التالية تعالج كل عامل على حدة.

### 15.9.1 تسريع الفحص: مرشّح رخيص قبل `find_tables()`

`find_tables()` تُجري تحليلاً هندسياً كاملاً للصفحة وتُعتبر من أبطأ عمليات PyMuPDF — استدعاؤها بلا داعٍ على صفحات هي أصلاً صور ممسوحة (حتى ولو فيها طبقة OCR نصية خفية تجعل `get_text()` غير فارغة) هو السبب الأكبر للبطء. الحل مطبَّق بكود الجزء 4 أعلاه: فحص `len(pg.get_drawings()) >= 4` أولاً (رخيص) قبل السماح باستدعاء `find_tables()` (مكلف) — يستبعد فوراً كل صفحة صورة بلا رسومات فعلية دون تحمّل كلفة التحليل الكامل.

| القياس | قبل المرشّح | بعد المرشّح |
|---|---|---|
| عدد استدعاءات `find_tables()` على ملف ممسوح 50 صفحة | 50 (كل صفحة) | 0 (لا رسومات) |
| الوقت التقريبي لهذه المرحلة وحدها | يتناسب خطياً مع تعقيد كل صفحة | ثوانٍ معدودة إجمالاً |

### 15.9.2 تسريع الرسترة: DPI تكيّفي + معالجة كسولة (Lazy)

- **DPI تكيّفي حسب الحاجة الفعلية:** 300 DPI افتراضي مبالغ به لصفحات نص عادي؛ يُخفَّض تلقائياً إلى 200 DPI ما لم يكشف `6.4` عيباً (دقة صغيرة/ضبابية) يستدعي 300+. توفير ~55% من حجم البيانات لكل صفحة دون خسارة دقة عملياً.
- **رسترة كسولة (Lazy Rasterization):** لا تُحوَّل كل صفحات الملف لصور دفعة واحدة عند الرفع؛ تُرستر الصفحة فقط لحظة الحاجة الفعلية لها بالطابور (15.8.1) — يمنع تجميد الواجهة على ملف 100+ صفحة قبل ما يشوف المستخدم أي شيء بشريط المصغّرات.
- **مصغّرات بدقة منخفضة منفصلة:** شريط المصغّرات (15.8.2) يستخدم رسترة سريعة بدقة عرض فقط (~150px) للتصفح الفوري، والرسترة الكاملة بدقة الاستخراج (200-300DPI) تحدث فقط لحظة الاستخراج الفعلي لكل عنصر — لا داعي لدقة استخراج كاملة لمجرد عرض مصغّرة بالواجهة.

### 15.9.3 تسريع النموذج: استدعاءات موازية بدل التسلسل

```python
import asyncio

async def extract_pages_parallel(pages: list, max_concurrent: int = 5):
    sem = asyncio.Semaphore(max_concurrent)   # يحترم حدود Rate Limit لكل مزود (الجزء 3)
    async def run_one(page):
        async with sem:
            return await extract_with_model(page)   # استدعاء غير متزامن للنموذج
    return await asyncio.gather(*(run_one(p) for p in pages))
```
- التوازي محدود بـ `max_concurrent` (افتراضياً 5، قابل للتعديل بالإعدادات) لاحترام حدود معدل الطلبات (Rate Limit) لكل مزود دون التسبب بأخطاء 429.
- تجربة عملية: ملف 30 صفحة ممسوحة بمعدل 5 ثوان/صفحة → **150 ثانية بالتسلسل** مقابل **~30 ثانية بالتوازي (5 متزامنة)** — تحسّن ~5×.
- شريط تقدّم بالواجهة يعرض تقدّم كل صفحة على حدة (منتظر/جارٍ/مكتمل/فشل) بدل شريط تحميل واحد صامت.

### 15.9.4 معالجة الملفات الكبيرة: تقسيم دفعي (Batching) + استئناف

- ملفات تتجاوز عتبة صفحات معيّنة (افتراضياً 40) تُقسَّم تلقائياً لدفعات (مثلاً كل 20 صفحة) تُعالَج وتُعرض نتائجها تباعاً بدل انتظار الملف كاملاً قبل أي عرض نتيجة.
- **استئناف عند الفشل الجزئي:** لو فشلت صفحة واحدة (خطأ شبكة/rate limit)، لا يُعاد استخراج الملف كاملاً — تُعاد محاولة الصفحة الفاشلة فقط ضمن نفس نتائج الدفعة (يتكامل مع سياسة إعادة المحاولة/Backoff الموجودة أصلاً بالخطة).

### 15.9.5 معايير قبول أداء (v7.1)

| المعيار | الهدف |
|---|---|
| استدعاءات `find_tables()` على صفحة صورة بلا رسومات | صفر |
| DPI الافتراضي | 200 ما لم يستدعِ محلل الجودة (6.4) رفعه |
| رسترة الصفحات | كسولة (عند الحاجة فقط)، لا دفعة واحدة عند الرفع |
| استدعاءات النموذج لملف متعدد الصفحات | موازية (حتى 5 متزامنة افتراضياً) لا تسلسلية |
| ملف >40 صفحة | يُعالَج بدفعات مع عرض نتائج تدريجي، لا انتظار كامل |
| فشل صفحة مفردة | إعادة محاولة الصفحة فقط، لا إعادة الملف كاملاً |

## 15.10 المرونة الإقليمية — التعامل مع حظر/تقييد المزودين حسب المنطقة الجغرافية

### 15.10.1 طبيعة المشكلة

بعض المزودات (OpenAI، Google Gemini، وأحياناً Anthropic) تُقيّد الوصول فعلياً من دول مشمولة بقيود تصدير أمريكية (سوريا، إيران، كوبا، كوريا الشمالية...) — هذا **حظر على مستوى الشبكة/الحساب**، لا علاقة له بصحة مفتاح API؛ حتى مفتاح صحيح 100% يفشل بهذه المناطق. بالمقابل مزودات كـ Qwen DashScope (صيني) أو نماذج محلية عبر Ollama لا تتأثر إطلاقاً بهذا النوع من القيود. النظام يجب أن **يميّز** هذا السبب تحديداً عن باقي أخطاء الاتصال، ويتعامل معه تلقائياً لا أن يُفشل العملية بصمت.

### 15.10.2 تصنيف الأخطاء (لا رسالة عامة "فشل الاتصال")

```python
class ProviderErrorType(Enum):
    GEO_BLOCKED   = "geo_blocked"     # 403/451 أو رسالة "unsupported_country_region_territory"
    AUTH_INVALID  = "auth_invalid"    # 401 مفتاح خاطئ/منتهي
    RATE_LIMITED  = "rate_limited"    # 429
    NETWORK_DOWN  = "network_down"    # timeout/DNS/اتصال مقطوع فعلياً
    UNKNOWN       = "unknown"

def classify_provider_error(response) -> ProviderErrorType:
    if response.status_code in (403, 451) or "unsupported_country" in response.text.lower():
        return ProviderErrorType.GEO_BLOCKED
    if response.status_code == 401: return ProviderErrorType.AUTH_INVALID
    if response.status_code == 429: return ProviderErrorType.RATE_LIMITED
    if response.status_code is None: return ProviderErrorType.NETWORK_DOWN   # timeout/connection error
    return ProviderErrorType.UNKNOWN
```
رسالة الواجهة تختلف جذرياً حسب النوع: "هذا المزود غير متاح بمنطقتك حالياً — جرّب مزوداً آخر أو نموذجاً محلياً" مختلفة تماماً عن "مفتاح API غير صحيح، تحقق من الإعدادات" — الخلط بينهما يُربك المستخدم ويجعله يظن مشكلة بحسابه وهي أصلاً حظر جغرافي لا علاقة له به.

### 15.10.3 فحص توفر دوري لكل مزود (Health Check)

```python
async def health_check_provider(provider) -> tuple[bool, ProviderErrorType | None]:
    try:
        resp = await provider.ping()          # طلب خفيف جداً (مثلاً /models وليس استدعاء نموذج كامل)
        return (True, None) if resp.ok else (False, classify_provider_error(resp))
    except (TimeoutError, ConnectionError):
        return (False, ProviderErrorType.NETWORK_DOWN)
```
- يُنفَّذ عند بدء التطبيق ولكل مزود مُفعَّل بالإعدادات، ويُعرض بتبويب الإعدادات كحالة حيّة: 🟢 متاح / 🔴 محظور بمنطقتك / 🟡 مفتاح غير صحيح / ⚪ غير مفعَّل.
- النتيجة تُخزَّن محلياً (`provider_status.json`) وتُحدَّث دورياً (كل بدء تشغيل + زر "إعادة الفحص" يدوي) — لا حاجة لانتظار فشل فعلي بمنتصف عملية استخراج لمعرفة أن مزوداً معيناً محظور.

### 15.10.4 ترتيب تلقائي يدمج "المتاح فعلياً" مع "المجاني أولاً"

ترتيب النماذج الحالي (`sort_models`, الطلب الأصلي "ترتيب المجانية أولاً") يُدمج الآن مع نتيجة الفحص الإقليمي بترتيب أولوية:

```python
def sort_models_regional(models, provider_status: dict):
    return sorted(models, key=lambda m: (
        not provider_status.get(m.provider, {}).get("available", True),  # المتاح فعلياً بمنطقتك أولاً
        not m.is_free,                                                    # ثم المجاني
        m.cost_per_1k_tokens                                              # ثم الأرخص
    ))
```
- مزود محظور بمنطقة المستخدم لا يختفي من القائمة (قد يعمل لاحقاً أو بشبكة مختلفة)، لكن يُدفع لأسفل القائمة تلقائياً وتظهر بجانبه شارة 🔴 بدل إخفائه بصمت.

### 15.10.5 سلسلة تراجع تلقائي عند التنفيذ الفعلي (Automatic Failover Chain)

```python
async def extract_with_failover(image, provider_chain: list, max_attempts=3):
    errors_log = []
    for provider in provider_chain:
        try:
            return await extract_with_model(image, provider)
        except ProviderError as e:
            err_type = classify_provider_error(e.response)
            errors_log.append((provider.name, err_type))
            if err_type == ProviderErrorType.GEO_BLOCKED:
                continue        # انتقل فوراً للمزود التالي، لا فائدة من إعادة المحاولة على نفس المزود
            elif err_type == ProviderErrorType.RATE_LIMITED:
                await asyncio.sleep(backoff_delay(...)); continue
            # AUTH_INVALID → لا تنتقل صامتاً، أبلغ المستخدم فوراً (قد يكون خطأً بجميع المزودات إن كان نفس السبب)
    raise AllProvidersFailedError(errors_log)   # رسالة نهائية تلخّص سبب فشل كل مزود على حدة، لا رسالة عامة
```
- لا يتم إخفاء الفشل الجزئي: لو نجح المزود الثالث بعد فشل الأول والثاني بحظر جغرافي، يُسجَّل هذا بسجل التدقيق (الجزء 9) لكل صفحة/سجل، مفيد لتشخيص مشاكل مستقبلية بنفس المنطقة.

### 15.10.6 خط الدفاع الأخير المضمون: Ollama المحلي

Ollama (مذكور أصلاً بقائمة المزودات) هو **الحل الوحيد المستقل تماماً عن أي قيود جغرافية**، لأنه يعمل بالكامل على جهاز/خادم المستخدم بدون أي اتصال خارجي لحظة الاستخراج نفسه (فقط تنزيل النموذج مرة واحدة عند الإعداد). يُوصى بإعداده تلقائياً كـ**آخر حلقة بسلسلة التراجع الافتراضية** لأي مستخدم بمنطقة معروفة بقيود متكررة، مع تنبيه بالإعدادات: "لضمان عمل النظام بأي ظرف شبكي، يُنصح بتفعيل نموذج محلي احتياطي عبر Ollama."

### 15.10.7 دعم نقطة نهاية مخصصة/وكيل (يستفيد من خيار "مخصص" الموجود أصلاً)

خيار "مخصص" بقائمة المزودات (الجزء 3.1) يُوثَّق صراحة كحل عملي لمناطق الحظر: يسمح للمستخدم بإدخال Base URL بديل (خادم وسيط/relay ذاتي الاستضافة يعيد توجيه الطلبات) بدل نقطة النهاية الرسمية المحظورة بمنطقته — لا تعديل كود مطلوب، فقط حقل إعداد موجود مسبقاً.
